# Generate the demo set in code and build its walkthrough without Rekordbox

## Context and Problem Statement

The docs walk through building a set from scratch, and should end on a preview page people can actually listen to. That
needs a set of house tracks that can be published, mixed and re-mixed freely. The docs are also built in CI, which has
no Rekordbox, while every step of auto-dj reads Rekordbox's beat grid and phrase analysis. Where does the music come
from, and how does the walkthrough run?

## Decision Drivers

- No copyright or licensing questions: the preview is a derivative mix, so even CC BY-ND music is out.
- DJ-friendly tracks (long intros and outros, breakdowns, a bassline that comes in after the intro), so the rules have
  something real to find.
- Reproducible: the docs build must produce the same tracks and the same cues every time, with nothing audio in git.
- Easy to listen to.

## Considered Options

- Creative Commons house tracks from Free Music Archive and netlabels
- Tracks generated with an AI music service (Gemini)
- A small synthesiser in the repository that renders original tracks

## Decision Outcome

Chosen option: "A small synthesiser in the repository", because it is the only option whose output we own outright, that
has DJ structure by construction, and that can be regenerated identically in CI.

- `internal/demo/synth` renders kick, clap and hats, an off-beat bass with a sub an octave down, chord stabs, a
  breakdown pad and a pluck lead, arranged in 16-bar phrases (intro, groove, main, breakdown with a build, drop, outro).
  Rendering is deterministic: no clock, a seeded random source, single-threaded per track.
- `internal/demo` defines ten tracks (key, tempo, progression, lead, bassline, stabs, arrangement). Their keys run round
  the Camelot wheel from 8A to 12A, except one track filed out of place so the key check has a clash to find.
- The generator knows each track's beat grid and phrases, so it supplies the analysis Rekordbox would. Audio features
  are measured from the rendered files as usual, and the real rules, set planner and preview code run on top.
  `apply --write` is replaced by putting the planned cues on the in-memory records.
- `auto-dj demo` runs all of it and opens the preview; the docs build runs the same command into `docs/demo/`
  (git-ignored) with the AIFFs under `build/`.
- The tracks are released CC0.

### Consequences

- Good, because the walkthrough's outputs are generated by the code they document, so they can't go stale.
- Good, because anyone can render the same ten AIFFs (`auto-dj demo`) and follow the walkthrough in Rekordbox.
- Bad, because the music is simple. It is pleasant enough for a tutorial, not a release.
- Bad, because Rekordbox's own analysis of the tracks may differ slightly from the generator's (a phrase label, a key
  spelling), so a reader's numbers can differ from the docs.
- Neutral, because floating-point results can differ between CPU architectures in the last bits, so the docs are
  reproducible per platform (CI always builds on the same one).

### Confirmation

Two `auto-dj demo` runs produce byte-identical files (tracks, MP3s, `set.json`, page and reports). The `internal/demo`
tests pin the analysis and the synthesiser's determinism.

## Pros and Cons of the Options

### Creative Commons house tracks

- Good, because they are real productions.
- Bad, because most netlabel house is CC BY-NC-ND, which forbids the preview mixes, and the CC BY material found was
  short production music in MP3, without DJ intros and outros, needing attribution on every page.

### AI-generated tracks (Gemini)

- Good, because they sound like finished songs.
- Bad, because they were about 3 minutes long in 196 kbps AAC, can't be regenerated in CI, and would have to be
  committed as audio.
